# I1.5 — Offline eval fixture spec (LitQA2 / BixBench frozen subset)

**Author:** S1 (idea) · **For:** imp1 / Lane 4 (`persona/eval/*`, owns FC-7). **Spec only — imp1 places the data + code in Lane-4 files.**
**Assigned by:** S0 dispatch 2026-07-13 (idea-lane task #1). **Binds:** FC-7 (`eval.run_oracle(name) -> {metric,score,n,per_item}`), master-res #15 (frozen offline subset for $0 demo), cache-the-demo discipline (CLAUDE.md §4). RQ-E15 gates the abstention-scoring magnitudes (see I1.6).

## 0. Non-negotiable: do NOT fabricate benchmark gold
LitQA2 and BixBench are **real published benchmarks** (FutureHouse). The fixture is a **frozen subset of the real items**, sourced + hash-pinned — never model-invented Q/A. If the real data can't be fetched offline at build time, ship an EMPTY fixture with `n:0` (imp1's stub already returns that) and a `sourcing_status:"unfetched"` marker — never synthesize items to fake a score. This is the same honesty rule as RQ-E01a exact-span admission.

## 1. Why
imp1 landed FC-7 `run_oracle` (stub) + the `/eval` route, but **no fixture data exists anywhere** — so RQ-E15 and F4.8 can't produce a real score. This spec defines the frozen fixture the oracle reads, offline and $0.

## 2. Fixture files (imp1 places under `persona/eval/fixtures/`)
```
persona/eval/fixtures/
  litqa2_subset.jsonl        # N frozen items (target N=25–50, stratified)
  litqa2_subset.sha256       # hash of the .jsonl, frozen BEFORE any run
  bixbench_subset.jsonl      # M frozen executable tasks (target M=5–10)
  bixbench_subset.sha256
  MANIFEST.json              # {benchmark, version/commit, source_url, license, n, selected_ids[], frozen_at_utc, subset_sha256}
```
The `.sha256` + MANIFEST are the "frozen before collection" guard (same discipline as the conflict-gold bundle in `ideas/001`).

## 3. Item schema
**LitQA2** (multiple-choice, abstention-aware — its defining feature is an "insufficient information" option):
```
{ id, question, options:[str], answer_idx:int,
  insufficient_idx:int,          # index of the "Insufficient information to answer" option
  source:{doi|pmid, title},      # the paper the answer requires (full-text retrieval target)
  gold_span:str|null }           # exact supporting passage if the benchmark provides it
```
**BixBench** (executable bioinformatics task):
```
{ id, task, dataset_ref, expected:{type:'numeric'|'categorical'|'set', value},
  tolerance:float|null,          # numeric match tolerance
  capsule_ref:str }              # points to the sandbox-runnable notebook/script (imp1 runs via existing sandbox)
```

## 4. Scoring (imp1 implements in `eval.run_oracle`; magnitudes gated by RQ-E15 — I1.6)
- **LitQA2 metric = abstention-aware accuracy.** Correct answer = +1; choosing `insufficient_idx` when the answer IS derivable = 0 (miss, not penalized as wrong); a WRONG confident answer = 0 and counts toward a separate **overconfidence rate**. Report `{metric:"litqa2_acc", score, n, per_item:[{id,picked,correct,abstained}], overconfidence_rate}`. Rewarding correct abstention over confident-wrong is the whole point — never collapse them.
- **BixBench metric = executed-match rate.** Run each capsule in the existing read-only sandbox (`tools/sandbox.py`), compare to `expected` under `tolerance`. Report `{metric:"bixbench_exec", score, n, per_item:[{id,ran:bool,matched:bool}]}`. A capsule that fails to run = `ran:false, matched:false` (loud, not silently skipped).
- **Determinism:** with a fixed `seed`, selection + ordering + score reproduce byte-identically; assert in the test.

## 5. Sourcing (imp1, offline-first)
1. Pull LitQA2 from the published FutureHouse release (pin the version/commit in MANIFEST); select a stratified subset (mix of answerable + genuinely-insufficient items so the abstention path is exercised). Record `selected_ids`.
2. Pull BixBench similarly; select tasks whose capsules run offline in the sandbox with data mounted read-only.
3. Freeze: write `.jsonl`, compute `.sha256`, write MANIFEST **before** the first scored run. Any later item change = new hash = new frozen subset (never edit in place).
4. If offline fetch isn't possible in the build env, ship empty (`n:0`, `sourcing_status:"unfetched"`) — the pipeline stays green, the score is honestly absent.

## 6. Acceptance gate
- **Runnable check** (`tests/test_eval_fixture.py`, pure/offline, $0): `run_oracle("litqa2", seed=0)` and `run_oracle("bixbench", seed=0)` return the FC-7 shape; if a fixture is present, `verify` the `.jsonl` matches its `.sha256` (tamper guard) and the score is deterministic across two calls; if empty, assert `n==0` and no crash.
- **RQ-E15 (I1.6)** sets whether the abstention-scoring magnitudes are defensible before any score drives a claim; until it passes, `run_oracle` output is **advisory/diagnostic**, not a gate.

## 7. Risks
- **Abstention gaming:** a model that always abstains scores 0 wrongs but also 0 corrects — report accuracy AND abstention rate AND overconfidence rate together so "always abstain" is visibly not a win.
- **License:** record each benchmark's license in MANIFEST; if redistribution isn't permitted, store `selected_ids` + a fetch script instead of the raw items.
- **Sandbox nondeterminism (BixBench):** reuse the E12a-hardened deterministic sandbox (frozen time, pinned image digest); a nondeterministic capsule is excluded from the frozen subset, not averaged in.
