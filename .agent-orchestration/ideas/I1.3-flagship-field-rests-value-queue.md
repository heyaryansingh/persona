# I1.3 — Flagship screen design contract: "Field-rests-on-this + value queue"

**Author:** S1 (idea) · **For:** imp1 / Lane 4 (Legibility flagship) to build against; imp4/Lane 3 provides FC-4. **Design contract — zero product code.**
**Binds:** PRD-00 §3–4 (FC-4), master-resolution #10 (VoI advisory until RQ-E17) + #13 (nav IA: this is a top destination). Frozen contracts in `HANDOFF.md` still bind. Cross-lane handoff = imp1 READS this + implements in its own lane; I never touch Lane-4 files.

## 1. What this screen answers (the one-line test)
A researcher opens the flagship and, in <10s, sees: **what the field currently rests on** (which beliefs carry the most downstream weight), **how fragile that footing is** (what collapses if a load-bearer falls), and **what to test next for the most information per dollar** (the value queue). It is the "scale of reading, discipline of believing, *and now* — leverage of acting" surface.

## 2. Data sources (consume FC-4 — do NOT recompute in the UI)
```
engine.dependency_graph() -> {
  nodes:[{claim_id, label, provenance_state, calibrated_p, anchored:bool,
          load_score:float,           # how many downstream beliefs depend on it
          fragility:float}],          # expected downstream confidence loss if it flips
  edges:[{from_claim, to_claim, kind:'premise'|'support'|'contradicts', weight}]
}
engine.value_queue() -> [{
  claim_id|question_id, title, voi:float,          # value-of-information rank
  cost_estimate:float, tier:'public_data'|'wetlab'|'expert',
  why:str, discriminating_test:str, advisory:bool   # advisory=true until RQ-E17 passes (#10)
}]
```
Everything rendered traces to a `claim_id` → deep-links into the Map evidence tree (I1.1). No number appears without a source link (legibility principle).

## 3. Three panels (one screen, no tabs)
| Panel | Shows | Interaction |
|---|---|---|
| **Field rests on this** | top-N claims by `load_score`, sized/sorted by weight; provenance-state colored; anchored ones marked | click → evidence tree (I1.1); hover → "N beliefs + M deliverables depend on this" |
| **Fragility** | for a selected load-bearer, the downstream cascade that would lose confidence if it flipped (the "what if this fell" preview) | select node → cascade highlights + a headline "X load-bearing beliefs at risk"; ties to backlog #26 fragility simulator |
| **Value queue** | ranked next tests by VoI with cost + tier; **advisory badge** until RQ-E17 | click "why" → discriminating test + evidence gap; `public_data` tier shows a "run" affordance (human-clicks, per #10 — NOT auto-dispatch) |

## 4. Honest-uncertainty rules (non-negotiable, from design principles)
- Provenance state drives visual authority: never render an `INFERRED`/`READ` load-bearer with the weight of a `HUMAN_CONFIRMED`/`TESTED` anchor.
- VoI ranks are **advisory** (badge + tooltip) until RQ-E17 passes; the UI must not imply the queue auto-acts. After RQ-E17, only `public_data`-tier **narrow** reanalyses may show auto-dispatch (Balanced autonomy, #10).
- `wetlab`/`expert`-tier items route to the human dossier (Judgment inbox, #13) — never actioned by Persona.
- Motion only on real state change (a belief's load_score shifting, a test landing, a new contradiction). No decorative animation.

## 5. Novelty vs competitors
- **scite / Open Targets:** show evidence *for a claim*; neither ranks the whole belief set by **downstream load** nor simulates **fragility cascades**. This screen makes "what the field rests on" a computed, interactive object.
- **PaperQA2:** answers one question; no persistent load/fragility model, no value queue.
- **MedKGent/KARMA/AutoBioKG:** build the graph; none surfaces a **value-of-information action queue** gated by calibrated autonomy. The *acting loop made legible* is Persona's contribution.

## 6. Acceptance gate (per HANDOFF: no feature done on prose)
- **Measurable criterion:** on the frozen demo corpus, the top-5 `load_score` claims match a human-annotated "these are load-bearing" set at ≥0.8 rank-overlap (freeze the annotation + hash before building).
- **Runnable check:** a `PERSONA_WORKERS=0` browser smoke that opens the flagship, asserts the three panels render from FC-4 fixtures, the advisory badge is present on VoI items, and every rendered number has a working claim deep-link (no dead links, no fabricated confidence). Plus a `pytest` asserting the FC-4 fixture→render contract shape.
- **Blocked-by:** FC-4 (`engine.dependency_graph`/`value_queue`) must land its stub first (imp4/Lane 3 Milestone-0). Until then, imp1 scaffolds against fixtures — do not block on live data.

## 7. Split / risks
- **Split:** imp4 provides FC-4; imp1 renders; imp1↔imp4 coordinate the fixture shape via a `requests/` note, not by cross-editing. This spec is the shared reference.
- **Risk — VoI not yet validated:** RQ-E17 gates auto-dispatch; if it fails, the queue stays permanently advisory — the screen must degrade gracefully to "human-curated next tests," not break.
- **Risk — load_score gaming:** a claim cited by many *low-confidence* derivations shouldn't outrank a true anchor; load_score should weight by downstream calibrated_p, not raw edge count. Flag for FC-4's definition (imp4).
