# I1.4 — The one Oracle-Verdict renderer (FC-8) design contract

**Author:** S1 (idea) · **For:** imp1 / Lane 4 (Legibility). **Design contract — zero product code.**
**Binds:** PRD-00 §4 FC-8 (+ CCP-16a controls/pipeline_health, CCP-18a READ/lookup capsule), oracle-guard routing (2026-07-13), master-res #10 (advisory), HANDOFF frozen contracts. Cross-lane handoff: imp1 READS this + builds in Lane-4 files; I never touch them.

## 1. Why one component
FC-8 says every code-run oracle (MR, DepMap, meta-analysis) **and** lookup oracle (LEGEND) returns the SAME envelope, and "Lane 4 renders every oracle with ONE component (verdict shaped like a `forensics.py` flag)." One renderer = consistency, and the honesty rules live in exactly one place instead of per-oracle. This is the **acting loop made legible**: a computed verdict a human can trust *or* correctly distrust.

## 2. The envelope it must render (do NOT reshape — consume as-is)
```
{ verdict|status, applicable:bool,
  methods:{}, sensitivity:{},                       # what was run; how robust
  capsule:{session_id, input_sha256, script_sha256, sandbox_image_digest},  # reproduction
  provenance:'TESTED-provisional'|'INFERRED'|'abstain'|'READ',
  high_stakes:bool, handoff_id?,
  controls?:{}, pipeline_health?:{},                # CCP-16a
  result_set?/cell_id?/source_doi?/release? }        # CCP-18a lookup capsule
```

## 3. Render rules (each maps an envelope field → an honest visual)
| Field | Visual | Rule |
|---|---|---|
| `applicable:false` | muted "**Not applicable**" state, reason shown | never render a verdict as a result when the oracle didn't apply — this is the F4.2/F3.8 skipped-vs-passed discipline |
| `provenance` | authority of the card | `TESTED-provisional` = strongest but badged *provisional*; `INFERRED` = weaker; `abstain` = "**no call**"; `READ` (lookup) = "**looked up, not computed**". Never render `INFERRED`/`abstain` with `TESTED` authority |
| `verdict` + `sensitivity` | headline + robustness strip | headline ALWAYS paired with its sensitivity (e.g. "holds under 3/3 checks" or "flips when FTL probes removed" — the E12b lesson). A verdict with no sensitivity shown is a bug |
| `capsule` | "Reproduce" affordance | show `input_sha256`/`script_sha256`/`sandbox_image_digest`; link to session replay. This is what makes the number auditable |
| `controls`/`pipeline_health` (CCP-16a) | quarantine banner | if control-injection tripped → verdict shown as `inconclusive`/quarantined with the failing control named; do NOT hide it |
| `high_stakes:true` | routes to Judgment inbox | render a "**needs human**" action to `handoff_id`; the card must NOT present a high-stakes oracle as a settled conclusion |
| advisory (master-res #10) | badge until the oracle's RQ gate passes | verdicts stay advisory (E21/E22/E24 per oracle) until validated; never imply auto-action |

## 4. Novelty
No competitor renders a *code-run acting verdict* with its reproduction capsule, control-injection state, and provenance-typed authority in one honest card. scite/OpenTargets show curated evidence; PaperQA2 answers; none exposes "here is the computation, its hashes, its controls, and exactly how much to trust it." This card is the trust surface for Persona's acting loop.

## 5. Acceptance gate (no feature done on prose)
- **Measurable:** across the 4 oracle fixture types (MR / DepMap / meta-analysis / LEGEND-lookup), the renderer produces the correct honesty state for a frozen matrix of envelopes — specifically it MUST render: an `applicable:false` as not-applicable (not a verdict), an `abstain` as no-call, a control-tripped envelope as quarantined, and a `high_stakes` as human-routed. Freeze the envelope matrix + expected states, hash it, before building.
- **Runnable check:** `pytest` asserting envelope→state mapping over the frozen matrix (pure, no paid calls) + a `PERSONA_WORKERS=0` browser smoke that opens one oracle card and asserts the capsule hashes + sensitivity strip + provenance badge are all present and every number deep-links.
- **Blocked-by:** FC-8 oracle stubs (imp4/Lane-3 routes `science.REGISTRY`; the MR/DepMap/meta oracle owners land envelopes). imp1 scaffolds against the frozen envelope matrix meanwhile.

## 6. Split / risks
- **Split:** oracle authors (Lane 3 + owners) produce envelopes; imp1 renders; the frozen envelope matrix is the shared fixture — coordinate its shape via `requests/`, not cross-edits.
- **Risk — silent non-applicability:** the single most important rule is #3 row 1: an oracle that didn't apply must never look like a null result. Make the not-applicable state visually distinct from an `abstain` no-call (different causes).
- **Risk — capsule absent:** a code-run oracle with no `capsule` hashes should render "**unverified computation**", not a clean verdict — fail loud.
