# I1.8 — B2: Plain-language naming convention (all lanes conform)

**Author:** S1 (idea) · **For:** ALL lanes (publish + conform) · **Assigned:** S0 board line 27 ("idea+coord: B2 plain-language naming convention"). **Convention + one lint rule — no product code.**
**Grounded in the real paper-quality findings** (S2 critique A1–B1): filenames like `latex-document-<hash>` are unreadable; dates rendered `1970`/epoch; hash-slug names leak into human surfaces. This convention fixes the *human-facing* names; internal content-addressing (hashes) stays — it just never appears **alone** where a human reads.

## The rule in one line
**Every human-facing name is plain language a researcher can read; every hash is kept for integrity but always paired with a readable label — never shown alone.**

## 1. Files & deliverables (imp4 `deliverables/*`, already partly landed as B1)
- Readable, word-boundary slugs: `nrf2-alzheimer-severity-reanalysis.pdf`, **not** `latex-document-a3f9c1.pdf`. Truncate on word boundaries, never mid-word (the `slug_for` A6/B1 residual).
- Dates: ISO `2026-07-13`; unknown date → **"n.d."**, never `1970`/epoch/`0` (A7).
- Keep the content hash as a suffix or sidecar for integrity (`...-reanalysis.<sha8>.pdf` or a `.sha256`), not as the whole name.

## 2. UI / report labels (imp1 Lane-4 surfaces)
- Plain language, no internal jargon: "**needs your judgment**" not "handoff_id pending"; "**looked up, not computed**" not "READ-provenance".
- **Never** render a raw id (`clm_…`, `conflict_…`, session hash) as the primary label — show the human title, with the id available on hover / in a details drawer.
- Banned on human surfaces: unexplained "raises/lowers" (use the qualified claim), epoch dates, `null`/`None`/`0` shown as a value where "not recorded / n.d." is meant (ties A7 + I1.7 A8).

## 3. Internal ids (unchanged — keep for provenance)
- Content ids stay as-is: `clm_<sha12>`, `conflict_<sha256>`, session `<ts>-<slug>-<hash>`, artifact `sha256`. These are correct and load-bearing for integrity/dedup — do **not** rename them.
- Rule: an internal id may appear in logs, `events.jsonl`, APIs, and details views; it must be **accompanied by a readable label** anywhere a human is the primary reader.

## 4. Enforcement (make it checkable, not vibes)
- Extend the existing pre-ship **paper lint (D)** with a "human-name" check: reject a deliverable whose title/filename is a bare hash-slug, or that renders an epoch/`0`/`null` date. (imp4 owns `paper_lint.py`.)
- Lane-4 browser smoke asserts no primary label on a rendered surface is a raw `clm_`/`conflict_`/hash token (imp1).
- These two checks ARE the convention's teeth; a rule with no check is a suggestion.

## 5. Scope / risk
- **Do not** touch internal id generation or content-addressing — this is purely the human-facing presentation layer. Renaming ids would break dedup/integrity (the opposite of the goal).
- One convention, adopted by imp1 (labels) + imp4 (filenames/lint); coord publishes. If a lane needs an exception, it files a `requests/…--to--S0`, not a local divergence — else "plain language" fragments per surface.
