**Author:** S1 · **For:** S0 → S4 (engine harness owner) · **Design contract only — zero code.**
**Binds:** CONTINUATION §7.8, `HANDOFF.md` swarm-reads-only contract. **GATED: paid live-model calls — needs explicit human budget greenlight + live model-name/cost probe (never trust `config.py`). Do NOT execute until S0 posts budget approval.**
**Grounded:** RQ-E07a (`experiments/exp_rq_e07a_swarm_physics.py`, `results/rq_e07a_swarm_physics.json`) — *replay* found central-source partitioning peaks in useful efficiency at **N=3**, effective team size saturates near **14–15** by N=100–1000, dense all-to-all sharing is harmful. Production default already moved 6→3 workers.

## 1. What's proven vs what this tests
RQ-E07a is a **replay** result: it re-partitions already-extracted claims. It does **not** prove live-model *reasoning* quality, sequential-task performance, or that topology choice survives real generation. This trial is the live, equal-token extension. **Claim to avoid (CONTINUATION §10):** do not celebrate agent count; the deliverable is *effective team size + validated novelty per token*, not throughput.

## 2. Hypothesis (falsifiable)
> Under a **fixed total token budget B**, allocation topology changes *validated novelty per token*. Specifically: parallel-breadth partitioning beats a single sequential-reasoning agent on validated-novel-claim yield up to an effective team size, beyond which marginal validated evidence falls below marginal cost — and dense all-to-all sharing is net-negative live (replicating E07a's replay finding under live models).

## 3. Independent variable — topology (equal-token across all arms)
Every arm gets the **same B total tokens** (input+output priced per the live probe), same question set, same seed set:
1. **Sequential-reasoning** — one agent, B tokens, iterative deepening (control).
2. **Parallel-breadth** — k disjoint source partitions + one reducer; sweep k ∈ {2,3,5,8,14,20}.
3. **Hierarchical cells** — cells of 3 readers → cell-reducer → top reducer.
4. **DAG handoff** — typed dependencies (reader→extractor→verifier) rather than flat fan-out.
5. **Reducer-bottleneck probe** — vary reducer share of B (does the reducer starve?).
6. **Marginal-evidence stopping** — dynamic k: stop spawning when marginal validated evidence/token < threshold.

## 4. Dependent metrics (the real ones)
- **Validated novelty:** count of claims that (a) pass the membrane — exact-span + independent sources, per RQ-E01a admission — AND (b) are not already in the belief-store. This is the numerator; prose volume is explicitly NOT a metric.
- **Effective team size:** the k at which marginal validated-novelty/token crosses below cost (diminishing-returns knee), reported per topology — the E07a definition carried to live models.
- **Validated-novelty-per-token** (primary efficiency score), cost, wall-latency, **correlated-error rate** (fraction of workers making the same wrong extraction — the poisoning risk).
- **Abstention correctness** (does the topology know when to stop / say "no new evidence").

## 5. Design (AGENTS.md §2, ≥20 seeds where stochastic)
- **Pilot first at small B** (budget-bounded) to price a single arm before committing the full sweep — report the pilot cost to S0, gate the full run on it.
- ≥20 seeds per (topology, k) cell via seeded question-order + partition shuffles; report mean ± 95% CI (percentile bootstrap, matching E07a's method).
- **Held-out question set** drawn from real Persona questions; freeze it + its hash before the run (no leakage).
- Save raw per-arm results to `results/rq_e07b_*` + a chart; **distinguish live vs replay evidence** in the writeup.
- **Go/No-go:** a topology "wins" only if its validated-novelty-per-token 95% CI clears the sequential control by a preregistered margin AND correlated-error rate does not rise. If no topology clears, the honest result is "sequential + N=3 partition stands" — report it, don't fish.

## 6. Novelty vs competitors
Multi-agent research stacks (AutoBioKG, KARMA orchestration, generic AutoGen/CrewAI swarms) report *agent count* and *task completion*. None reports **effective team size under a fixed token budget with membrane-validated novelty as the yield metric and correlated-error as a guard.** Persona's contribution is treating the swarm as a measured physical system with a cost-bounded efficiency frontier, not a bigger-is-better demo.

## 7. Risks / guards
- **Cost blowout** — the whole reason it's human-budget-gated; the small-B pilot is the circuit breaker.
- **Correlated errors** — more workers reading overlapping sources can amplify one bad extraction; the correlated-error metric is a first-class dependent variable, not an afterthought.
- **Membrane must stay the arbiter** — swarm READS only; validated-novelty is counted *after* the membrane, never from raw agent output (frozen contract).
- If live budget never lands, deliver the **frozen harness + preregistration** (design done, execution deferred) — same discipline as the conflict-gold bundle in `ideas/001`.
