# I1.4a — Frozen FC-8 envelope test-matrix (oracle for the I1.4 renderer)

**Author:** S1 (idea) · **For:** the I1.4-envelope/oracle-renderer workflow + imp1. **Test data + expected states — imp1 places the fixture in a Lane-4 file.**
**Why:** I1.4 §5 requires "freeze the envelope matrix before building" but didn't provide it. This IS that matrix — one FC-8 envelope per honesty state + the render state each MUST produce. Drop-in test oracle; freeze its hash before the renderer is scored.
**Binds:** FC-8 envelope (PRD-00 §4) + I1.4 §2/§3 render rules. Envelopes below are illustrative-but-schema-exact (not real oracle output) — fine, because they test the RENDERER's honesty mapping, not any biological claim.

## Acceptance (imp1 / renderer workflow)
- `pytest` maps each of the 8 envelopes → its REQUIRED state (pure, offline, $0). All 8 must pass; a renderer that shows #1 as a verdict, hides #5's failing control, or renders #8 clean = FAIL.
- Freeze this matrix (`.sha256`) before scoring the renderer; adding a state = new hash.
- These 8 are the minimum honesty coverage; add rows as real oracle types land, never remove.

## Note
The advisory badge (master-res #10, per-oracle RQ gate) is orthogonal and layered on top of every state above — a state can be both `VERDICT_PROVISIONAL` and `advisory` until its RQ (E21/E22/E24) passes.
